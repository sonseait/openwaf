# Overview request-window counts

`GET /api/v1/telemetry/window` is session-authenticated and returns gateway request-start counts from process-local memory; it does not query ClickHouse or count completed/logged records. Query parameters: optional `host`, optional `path_prefix`, and `window_seconds` (1–900; default 900). Host matching is ASCII case-insensitive. Path matching is a literal, case-sensitive prefix against the raw URI path, excluding its query string (`/api` matches `/apix`). Prefixes are limited to 2,048 bytes; host values to 253 bytes. Invalid filters return the standard API validation error.

The counter retains up to 512 distinct normalized-host/raw-path keys, each with 900 one-second buckets (about 7.4 MiB for bucket payload at maximum, excluding map/key overhead). Starts are recorded after host normalization in gateway request filtering, before WAF/routing completion. It resets at process restart; data is live only, with no historical backfill. The admin overview polls once per second; pause stops polling after one final refresh and resume resumes updates.

`complete` is false and `overflow_requests` nonzero if the bounded key limit or nonblocking lock contention caused missed observations. No new key is evicted to make room. Long or structurally invalid request paths are dropped and reflected in the overflow count when the registry lock is available. A zero count is not available until an authenticated API response succeeds; errors are not rendered as zero. The source is `gateway_request_starts`, and `observed_at_unix_ms`, `coverage_start_unix_ms`, window bounds, tracked keys, capacity, and reset semantics accompany each result. `complete` remains false during startup until the registry has observed a full requested window. This is a local bounded operational estimate, not a durable accounting ledger.
